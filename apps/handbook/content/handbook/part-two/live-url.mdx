You have a version that works in your development environment. Now it needs an address your friend can open from their own device. Deploying puts the application on hosting that can run it when your development preview is closed.

We'll use Prisma Compute for the hosted version. Its [getting started guide](https://www.prisma.io/docs/compute/getting-started) covers deploying an application and checking the result. The exact path for this walkthrough needs to match the project created by Product Builder.

## Know which version you're putting online

Start from the working checkpoint you tested in the last chapter. Save any changes you intend to include. If you've been experimenting in another version, check that you're deploying the one you actually tried.

Pick the Prisma workspace and application that should hold this product. Check the destination before the deployment runs, especially if your account also contains other projects. This first release is for a friend trial with sample data.

Hosting can have costs and usage limits. Review the service's current plan as part of setup, and know where to see usage. You don't need a custom domain for this trial; the address provided by the host is enough if your friend can reach it.

## Connect the hosted app to the right data

The hosted application needs its own configuration. A database connection that works in your local environment isn't evidence that the deployed app can use it.

Configuration supplied outside the code is often called an environment variable. A database URL is one example. Keep secret values in the project's supported configuration or secret storage, rather than putting them in a page, a public repository, or an AI message.

Decide which database this trial should use. Keep it separate from data you need to preserve while experimenting. Don't assume that a new application URL automatically means a new database; check the actual connection.

The hosted database also needs the structure the current code expects. Confirm how the project applies those changes and whether the deployment includes that step. If the flow uses sign-in or invitation links, check that their destinations use the hosted address too.

## Work through deployment with the AI

Ask the AI to inspect the project before choosing commands. If Product Builder already provides a deployment workflow, use that workflow and its configuration.

```text title="Prepare the friend-trial deployment"
Inspect this project's setup and documented Prisma deployment path.
Identify the version to deploy, the destination workspace and app,
and the database the hosted version will use.

List missing configuration by name without displaying secret values.
Check whether database setup is included or needs a separate step.
Run the project's build and relevant checks, and resolve failures.

Use the deployment path supported by this project and the installed
tools. After deploying to the selected trial destination, give me
the public URL and verify that it responds. Explain how to inspect
logs and deploy the next change.
```

If deployment fails, capture the specific error and investigate it before changing unrelated code. An error while building the application can have a different cause from an application that starts but can't load data. The deployment output and application logs help you distinguish them.

## Test the public address

Open the public URL yourself, then open it on another device or in a separate browser session. A `localhost` address refers to the device opening it, so it won't take your friend to your application on your computer.

Repeat the complete task on the hosted version. Create a request, open it through the client's access path, submit a response, and confirm the designer can read it. Refresh and check that it remains saved.

Check any access restriction on the hosting preview as well as the application's own access rules. Your friend may need an invitation to the host, the app, or both. Use the same path they'll receive so you can find that out before sending it.

Then close your local development preview and try the hosted flow again. Record the working URL and the version you deployed. You're ready to [give it to a friend](./friend.mdx).
